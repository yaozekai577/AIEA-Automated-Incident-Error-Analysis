## 1. 设计概述

### 1.1 设计原则

| 原则 | 说明 |
|------|------|
| **结构化存储** | 事件、分析、通知、工单、配置等全部落库，确保可追溯 |
| **外键约束** | 分析结果通过外键关联事件，保证数据完整性 |
| **索引优化** | 对高频查询字段（fingerprint、status、event_id、created_at）建立索引 |
| **utf8mb4 字符集** | 支持完整 Unicode（含中文、emoji），COLLATE 使用 `utf8mb4_unicode_ci` |
| **InnoDB 引擎** | 支持事务、行级锁、外键，适合 OLTP 场景 |
| **JSON 类型** | 上下文和修复建议使用 MySQL 原生 JSON 类型，支持结构化存储 |
| **配置外置** | LLM 等可变配置存入 `system_config` 表，支持运行时热更新 |

### 1.2 数据库基本信息

| 属性 | 值 |
|------|-----|
| 数据库名 | `aiea` |
| 字符集 | `utf8mb4` |
| 排序规则 | `utf8mb4_unicode_ci` |
| 存储引擎 | `InnoDB` |
| 表数量 | 10 |
| ORM | Spring Data JPA（Hibernate） |
| DDL 策略 | `ddl-auto: none`（使用 init.sql 手动管理） |

## 4. 表结构详细设计

### 4.1 error_event — 错误事件主表

错误事件的接入主表，所有上报的异常都记录在此表中。

**状态机**: `RECEIVED → ANALYZING → NOTIFIED → TICKETED → FAILED`；`SUPPRESSED`（冷却窗口内重复上报）

| 字段名 | 数据类型 | 可空 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| `id` | BIGINT, AUTO_INCREMENT | NOT NULL | — | 主键 ID |
| `fingerprint` | VARCHAR(64) | NOT NULL | — | 错误指纹（归一化堆栈 SHA-256 哈希，64 字符） |
| `env` | VARCHAR(32) | NOT NULL | `'local'` | 环境标识：`local` / `dev` / `staging` / `prod` |
| `service` | VARCHAR(128) | NOT NULL | — | 上报服务名（与 `service_registry.service` 对应） |
| `message` | VARCHAR(1024) | NULL | — | 异常 message（最长 1024 字符） |
| `stack` | TEXT | NULL | — | 完整堆栈（SDK 侧截断至 32KB，Server 侧截断至 32768 字符） |
| `context_json` | JSON | NULL | — | 上下文 JSON（版本/host/thread/MDC/traceId 等） |
| `status` | VARCHAR(32) | NOT NULL | `'RECEIVED'` | 处理状态（见状态机） |
| `created_at` | DATETIME | NOT NULL | `CURRENT_TIMESTAMP` | 创建时间 |
| `updated_at` | DATETIME | NOT NULL | `CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` | 更新时间 |

**索引**:

| 索引名 | 类型 | 字段 | 用途 |
|--------|------|------|------|
| `PRIMARY` | 主键 | `id` | 主键索引 |
| `idx_fingerprint` | 普通索引 | `fingerprint` | 按指纹查询/聚合 |
| `idx_status` | 普通索引 | `status` | 按状态过滤 |
| `idx_env_service` | 联合索引 | `(env, service)` | 按环境+服务查询 |
| `idx_created_at` | 普通索引 | `created_at` | 按时间排序/统计 |

**JPA 实体**: `com.yzk.aiea.entity.ErrorEvent`

**context_json 示例**:
```json
{
  "hostname": "prod-server-01",
  "thread": "http-nio-8080-exec-3",
  "releaseVersion": "1.2.0",
  "traceId": "trace-9a8b7c6d",
  "userId": "12345",
  "url": "/api/orders/123"
}
```

### 4.2 analysis_result — AI 根因分析结果

大模型根因分析结果，与 `error_event` 一对一关联。`event_id` 同时为主键和外键。

| 字段名 | 数据类型 | 可空 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| `event_id` | BIGINT | NOT NULL | — | 主键 + 外键 → `error_event.id`（一对一） |
| `root_cause` | TEXT | NULL | — | 根因分析描述 |
| `suggestions` | JSON | NULL | — | 修复建议（Top N 列表，JSON 数组） |
| `confidence` | DECIMAL(5,4) | NULL | — | 置信度 0~1（如 0.8500 表示 85%） |
| `model` | VARCHAR(128) | NULL | — | 使用的模型名（如 `qwen-plus`） |
| `raw_response` | TEXT | NULL | — | LLM 原始返回内容 |
| `created_at` | DATETIME | NOT NULL | `CURRENT_TIMESTAMP` | 创建时间 |

**约束**:

| 约束名 | 类型 | 说明 |
|--------|------|------|
| `PRIMARY` | 主键 | `event_id` |
| `fk_analysis_event` | 外键 | `event_id` → `error_event.id` |

**JPA 实体**: `com.yzk.aiea.entity.AnalysisResult`

**suggestions 示例**:
```json
[
  "添加空指针检查：在使用 getUser() 返回值前判断是否为 null",
  "使用 Optional 包装返回值：Optional.ofNullable(userRepository.findById(id))",
  "在 Repository 层添加 @NonNull 注解，静态检查辅助"
]
```

### 4.5 suppress_rule — 告警抑制规则

告警抑制/冷却规则，以指纹为主键。每个指纹对应一条冷却规则。

| 字段名 | 数据类型 | 可空 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| `fingerprint` | VARCHAR(64) | NOT NULL | — | 主键，错误指纹 |
| `cooldown_sec` | INT | NOT NULL | `600` | 冷却窗口（秒），可调整范围 1~86400 |
| `last_fired_at` | DATETIME | NULL | — | 上次触发时间（用于计算剩余冷却时间） |
| `hit_count` | INT | NOT NULL | `0` | 命中/合并次数（冷却窗口内重复上报的次数） |

**索引**:

| 索引名 | 类型 | 字段 | 用途 |
|--------|------|------|------|
| `PRIMARY` | 主键 | `fingerprint` | 主键索引 |

**JPA 实体**: `com.yzk.aiea.entity.SuppressRule`

**说明**: 此表与 Redis 配合使用。Redis 中维护实时冷却窗口（SET NX + INCR + TTL），此表持久化冷却规则配置和历史命中统计。Redis 不可用时，系统降级为放行（不抑制）。

### 4.6 internal_ticket — 内置工单

不依赖外部 Jira 的完整工单生命周期管理。同指纹有未关闭工单时复用。

**状态机**: `OPEN → IN_PROGRESS → RESOLVED → CLOSED` / `IGNORED`（支持 `REOPEN`）

| 字段名 | 数据类型 | 可空 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| `id` | BIGINT, AUTO_INCREMENT | NOT NULL | — | 主键 ID |
| `event_id` | BIGINT | NOT NULL | — | 关联事件 ID（首次触发创建工单的事件） |
| `fingerprint` | VARCHAR(64) | NOT NULL | — | 错误指纹（同指纹复用工单） |
| `title` | VARCHAR(255) | NOT NULL | — | 工单标题（AI 生成，失败时降级为拼接标题） |
| `status` | VARCHAR(32) | NOT NULL | `'OPEN'` | 工单状态（见状态机） |
| `priority` | VARCHAR(16) | NOT NULL | `'P2'` | 优先级：`P0` / `P1` / `P2` / `P3` |
| `assignee` | VARCHAR(128) | NULL | — | 处理人 |
| `resolution` | TEXT | NULL | — | 解决方案（RESOLVED 时填写） |
| `created_at` | DATETIME | NOT NULL | `CURRENT_TIMESTAMP` | 创建时间 |
| `updated_at` | DATETIME | NOT NULL | `CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` | 更新时间 |
| `resolved_at` | DATETIME | NULL | — | 解决时间 |
| `closed_at` | DATETIME | NULL | — | 关闭时间（CLOSED 或 IGNORED 时设置） |

**索引**:

| 索引名 | 类型 | 字段 | 用途 |
|--------|------|------|------|
| `PRIMARY` | 主键 | `id` | 主键索引 |
| `idx_event_id` | 普通索引 | `event_id` | 按事件查询工单 |
| `idx_fingerprint` | 普通索引 | `fingerprint` | 按指纹查找复用工单 |
| `idx_status` | 普通索引 | `status` | 按状态过滤工单列表 |
| `idx_assignee` | 普通索引 | `assignee` | 按处理人过滤工单列表 |

**JPA 实体**: `com.yzk.aiea.entity.InternalTicket`

**优先级判定规则**（创建时自动判定）:

| 优先级 | 触发关键词 | 说明 |
|--------|-----------|------|
| P0 | `OutOfMemoryError`、`StackOverflowError`、`Deadlock` | 最高优先级 |
| P1 | `NullPointerException`、`SQLException`、`DataAccessException` | 高优先级 |
| P2 | 默认 | 中等优先级 |
| P3 | 手动设置 | 低优先级 |

### 4.7 ticket_log — 工单操作日志

工单操作记录（处理时间线），与 `internal_ticket` 一对多关联。

| 字段名 | 数据类型 | 可空 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| `id` | BIGINT, AUTO_INCREMENT | NOT NULL | — | 主键 ID |
| `ticket_id` | BIGINT | NOT NULL | — | 关联工单 ID（逻辑外键 → `internal_ticket.id`） |
| `action` | VARCHAR(32) | NOT NULL | — | 操作类型（见下方枚举） |
| `old_value` | VARCHAR(255) | NULL | — | 变更前值 |
| `new_value` | VARCHAR(255) | NULL | — | 变更后值 |
| `operator` | VARCHAR(128) | NULL | — | 操作人（默认 `anonymous`） |
| `remark` | TEXT | NULL | — | 备注（如忽略原因、重开原因） |
| `created_at` | DATETIME | NOT NULL | `CURRENT_TIMESTAMP` | 创建时间 |

**索引**:

| 索引名 | 类型 | 字段 | 用途 |
|--------|------|------|------|
| `PRIMARY` | 主键 | `id` | 主键索引 |
| `idx_ticket_id` | 普通索引 | `ticket_id` | 按工单查询操作日志 |

**JPA 实体**: `com.yzk.aiea.entity.TicketLog`

**action 枚举值**:

| action | 说明 | 触发场景 |
|--------|------|---------|
| `CREATE` | 创建工单 | 异步流水线自动创建 |
| `CLAIM` | 认领工单 | 用户认领，OPEN → IN_PROGRESS |
| `STATUS` | 状态变更 | 认领时的自动状态变更记录 |
| `RESOLVE` | 解决工单 | 用户标记已解决 |
| `CLOSE` | 关闭工单 | 用户关闭工单 |
| `IGNORE` | 忽略工单 | 用户标记忽略 |
| `REOPEN` | 重新打开 | 用户重开 / 错误复发自动重开 |
| `PRIORITY` | 优先级变更 | 用户变更优先级 |
| `RECURRENCE` | 错误复发 | 冷却窗口内错误复发，追加到时间线 |

## 5. 状态机设计

### 5.1 错误事件状态机

```
                    ┌──────────┐
   上报成功          │ RECEIVED  │ 事件已入库，等待异步流水线
   ──────────────►  │          │
                    └────┬─────┘
                         │ 异步流水线启动
                         ▼
                    ┌──────────┐
                    │ ANALYZING│ AI 分析中
                    │          │
                    └────┬─────┘
                         │ 分析完成
              ┌──────────┼──────────┐
              │          │          │
              ▼          ▼          ▼
     ┌──────────┐ ┌──────────┐ ┌──────────┐
     │ NOTIFIED │ │ TICKETED │ │  FAILED  │
     │  已通知   │ │ 已建单   │ │  处理失败 │
     └──────────┘ └──────────┘ └──────────┘
                                  │
                                  │ 手动重试
                                  ▼
                              回到 RECEIVED

   ┌──────────┐
   │SUPPRESSED│ 冷却窗口内重复上报，不进入流水线
   └──────────┘
```

| 状态 | 说明 | 触发条件 |
|------|------|---------|
| `RECEIVED` | 已入库，等待处理 | 上报成功，不在冷却窗口内 |
| `ANALYZING` | AI 分析中 | 异步流水线启动 |
| `NOTIFIED` | 已通知 | 飞书/钉钉推送完成 |
| `TICKETED` | 已建单 | 工单创建完成 |
| `FAILED` | 处理失败 | LLM/通知/建单失败 |
| `SUPPRESSED` | 被抑制 | 冷却窗口内重复上报 |

### 5.2 内置工单状态机

```
   ┌─────────────────────────────────────────────────────────┐
   │                                                         │
   ▼                                                         │
┌──────────┐    认领     ┌──────────────┐    解决    ┌──────────┐    关闭    ┌──────────┐
│   OPEN   │──────────►│ IN_PROGRESS  │─────────►│ RESOLVED │─────────►│  CLOSED  │
│          │           │              │           │          │           │          │
└──────────┘           └──────────────┘           └──────────┘           └──────────┘
                               ▲                      │                      │
                               │                      │ 忽略                  │ 忽略
                               │                      ▼                      ▼
                               │                 ┌──────────┐           ┌──────────┐
                               │                 │ IGNORED  │           │          │
                               │                 │          │           │          │
                               │                 └──────────┘           │          │
                               │                      │                  │          │
                               └──────────────────────┴──────────────────┘          │
                                  REOPEN (重新打开)                                   │
                                                                                   │
                               ┌──────────────────────────────────────────────────┘
                               │  REOPEN
                               ▼
                          IN_PROGRESS
```

| 状态 | 说明 | 可执行操作 |
|------|------|-----------|
| `OPEN` | 新创建，待认领 | 认领、忽略、变更优先级 |
| `IN_PROGRESS` | 处理中 | 解决、忽略、变更优先级 |
| `RESOLVED` | 已解决 | 关闭、重开 |
| `CLOSED` | 已关闭 | 重开 |
| `IGNORED` | 已忽略 | 重开 |

### 5.3 通知推送状态

通知推送通过 `notify_record.http_status` 记录结果：

| HTTP 状态码 | 含义 | 处理 |
|-------------|------|------|
| 200 | 推送成功 | 记录成功 |
| 4xx | 客户端错误（Webhook 地址错误等） | 重试（最多 3 次） |
| 5xx | 服务端错误 | 重试（最多 3 次） |
| null | 连接失败/超时 | 重试（最多 3 次） |

### 6.2 索引设计原则

1. **主键索引**: 所有表均有自增主键（除 `analysis_result`、`suppress_rule`、`system_config` 使用业务主键）
2. **外键索引**: 所有逻辑外键字段（`event_id`、`ticket_id`）均建立普通索引，加速关联查询
3. **查询索引**: 高频查询条件（`fingerprint`、`status`、`assignee`）单独建索引
4. **联合索引**: `idx_env_service` 覆盖仪表盘按环境+服务的联合查询场景
5. **唯一约束**: `service`、`api_token`、`jira_key`、`(service, channel)` 使用唯一索引保证数据一致性

## 8. Redis 数据结构设计

AIEA 使用 Redis 作为缓存层，与 MySQL 配合使用。以下为 Redis 中的数据结构设计：

### 8.1 指纹冷却/去重

| 属性 | 值 |
|------|-----|
| **Key 格式** | `aiea:dedup:{fingerprint}` |
| **数据类型** | String |
| **操作** | `SET NX` + `INCR` + `EXPIRE` |
| **TTL** | `cooldown_sec` 秒（可配置，默认 120 秒） |
| **用途** | 冷却窗口去重，冷却期内同类错误合并计数 |
| **降级策略** | Redis 不可用时降级为放行（不抑制） |

**工作流程**:
```
1. SET aiea:dedup:{fp} 0 NX EX {cooldown_sec}   → 首次设置成功 = 新错误，放行
2. INCR aiea:dedup:{fp}                           → 已存在 = 重复错误，计数+1，抑制
3. 返回 hitCount
```

### 8.2 限流

| 属性 | 值 |
|------|-----|
| **Key 格式** | `aiea:rate:global:{timestamp}` / `aiea:rate:{service}:{timestamp}` |
| **数据类型** | String（计数器） |
| **算法** | 固定窗口 |
| **TTL** | 1 秒 |
| **用途** | 全局 QPS 限制（默认 100）+ 每服务 QPS 限制（默认 20） |
| **降级策略** | Redis 不可用时降级为不限流 |

### 8.3 LLM 分析缓存

| 属性 | 值 |
|------|-----|
| **Key 格式** | `aiea:llm:cache:{fingerprint}` |
| **数据类型** | String（JSON 序列化的 AnalysisResult） |
| **TTL** | `analysis-cache-ttl` 秒（可配置，默认 3600 秒，0=不缓存） |
| **用途** | 同指纹 TTL 窗口内复用分析结果，避免重复消耗 LLM Token |
| **降级策略** | Redis 不可用时降级为不缓存，每次都调用 LLM |

## 10. 完整建表脚本

> 以下为完整建表脚本，与 `src/main/resources/db/init.sql` 一致。

```sql
-- ============================================================
-- AIEA 数据库初始化脚本 (MySQL 8)
-- ============================================================

-- 建库
CREATE DATABASE IF NOT EXISTS aiea
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

USE aiea;

-- ------------------------------------------------------------
-- 1. error_event : 错误事件（接入主表）
--    状态机: RECEIVED -> ANALYZING -> NOTIFIED -> TICKETED -> FAILED
--          SUPPRESSED (冷却窗口内重复上报，不进入流水线)
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS error_event (
  id            BIGINT       NOT NULL AUTO_INCREMENT,
  fingerprint   VARCHAR(64)  NOT NULL COMMENT '错误指纹(归一化堆栈哈希)',
  env           VARCHAR(32)  NOT NULL DEFAULT 'local' COMMENT 'local/dev/staging/prod',
  service       VARCHAR(128) NOT NULL COMMENT '上报服务名',
  message       VARCHAR(1024) NULL COMMENT '异常 message',
  stack         TEXT         NULL COMMENT '完整堆栈',
  context_json  JSON         NULL COMMENT '上下文(版本/host/thread/MDC 等)',
  status        VARCHAR(32)  NOT NULL DEFAULT 'RECEIVED' COMMENT '处理状态机',
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  INDEX idx_fingerprint (fingerprint),
  INDEX idx_status (status),
  INDEX idx_env_service (env, service),
  INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- ------------------------------------------------------------
-- 2. analysis_result : 大模型根因分析结果
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS analysis_result (
  event_id      BIGINT       NOT NULL COMMENT '关联 error_event.id',
  root_cause    TEXT         NULL COMMENT '根因分析',
  suggestions   JSON         NULL COMMENT '修复建议(Top N)',
  confidence    DECIMAL(5,4) NULL COMMENT '置信度 0~1',
  model         VARCHAR(128) NULL COMMENT '使用的模型',
  raw_response  TEXT         NULL COMMENT 'LLM 原始返回',
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (event_id),
  CONSTRAINT fk_analysis_event FOREIGN KEY (event_id) REFERENCES error_event (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- ------------------------------------------------------------
-- 3. notify_record : 协作推送记录(飞书/钉钉)
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS notify_record (
  id            BIGINT       NOT NULL AUTO_INCREMENT,
  event_id      BIGINT       NOT NULL,
  channel       VARCHAR(32)  NULL COMMENT 'feishu/dingtalk',
  payload       TEXT         NULL COMMENT '推送报文(Markdown/卡片 JSON)',
  http_status   INT          NULL COMMENT '推送 HTTP 状态码',
  sent_at       DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  INDEX idx_event_id (event_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- ------------------------------------------------------------
-- 4. jira_ticket : Jira 工单关联
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS jira_ticket (
  id            BIGINT       NOT NULL AUTO_INCREMENT,
  event_id      BIGINT       NOT NULL,
  jira_key      VARCHAR(64)  NOT NULL COMMENT 'Jira Issue Key(如 AIEA-123)',
  project       VARCHAR(64)  NULL COMMENT 'Jira 项目 Key',
  url           VARCHAR(512) NULL COMMENT 'Jira Issue URL',
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_jira_key (jira_key),
  INDEX idx_event_id (event_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- ------------------------------------------------------------
-- 5. suppress_rule : 告警抑制/冷却规则
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS suppress_rule (
  fingerprint    VARCHAR(64) NOT NULL COMMENT '错误指纹(粗键)',
  cooldown_sec   INT         NOT NULL DEFAULT 600 COMMENT '冷却窗口(秒)',
  last_fired_at  DATETIME    NULL COMMENT '上次触发时间',
  hit_count      INT         NOT NULL DEFAULT 0 COMMENT '命中/合并次数',
  PRIMARY KEY (fingerprint)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- ------------------------------------------------------------
-- 6. internal_ticket : 内置工单（替代外部 Jira）
--    状态: OPEN -> IN_PROGRESS -> RESOLVED -> CLOSED / IGNORED
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS internal_ticket (
  id            BIGINT       NOT NULL AUTO_INCREMENT,
  event_id      BIGINT       NOT NULL COMMENT '关联 error_event.id',
  fingerprint   VARCHAR(64)  NOT NULL COMMENT '错误指纹(同指纹复用工单)',
  title         VARCHAR(255) NOT NULL COMMENT '工单标题',
  status        VARCHAR(32)  NOT NULL DEFAULT 'OPEN' COMMENT 'OPEN/IN_PROGRESS/RESOLVED/CLOSED/IGNORED',
  priority      VARCHAR(16)  NOT NULL DEFAULT 'P2' COMMENT 'P0/P1/P2/P3',
  assignee      VARCHAR(128) NULL COMMENT '处理人',
  resolution    TEXT         NULL COMMENT '解决方案(RESOLVED 时填写)',
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  resolved_at   DATETIME     NULL COMMENT '解决时间',
  closed_at     DATETIME     NULL COMMENT '关闭时间',
  PRIMARY KEY (id),
  INDEX idx_event_id (event_id),
  INDEX idx_fingerprint (fingerprint),
  INDEX idx_status (status),
  INDEX idx_assignee (assignee)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- ------------------------------------------------------------
-- 7. ticket_log : 工单操作记录（处理时间线）
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS ticket_log (
  id            BIGINT       NOT NULL AUTO_INCREMENT,
  ticket_id     BIGINT       NOT NULL COMMENT '关联 internal_ticket.id',
  action        VARCHAR(32)  NOT NULL COMMENT 'CREATE/CLAIM/RESOLVE/CLOSE/IGNORE/REOPEN/PRIORITY',
  old_value     VARCHAR(255) NULL COMMENT '变更前值',
  new_value     VARCHAR(255) NULL COMMENT '变更后值',
  operator      VARCHAR(128) NULL COMMENT '操作人',
  remark        TEXT         NULL COMMENT '备注',
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  INDEX idx_ticket_id (ticket_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- ------------------------------------------------------------
-- 8. notify_routing : 通知路由规则（服务名 + 渠道 → Webhook）
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS notify_routing (
  id            BIGINT       NOT NULL AUTO_INCREMENT,
  service       VARCHAR(128) NOT NULL COMMENT '业务服务名(对应 error_event.service)',
  channel       VARCHAR(32)  NOT NULL DEFAULT 'feishu' COMMENT '通知渠道: feishu / dingtalk',
  webhook_url   VARCHAR(512) NOT NULL COMMENT 'IM 自定义机器人 Webhook 地址',
  description   VARCHAR(255) NULL COMMENT '描述(如: 订单服务专属飞书群)',
  enabled       TINYINT(1)   NOT NULL DEFAULT 1 COMMENT '是否启用(1=启用, 0=禁用)',
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_service_channel (service, channel)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- ------------------------------------------------------------
-- 9. service_registry : 服务注册与上报鉴权（每服务一个 Token）
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS service_registry (
  id            BIGINT       NOT NULL AUTO_INCREMENT,
  service       VARCHAR(128) NOT NULL COMMENT '业务服务名(对应 error_event.service)',
  api_token     VARCHAR(128) NOT NULL COMMENT '服务专属上报 Token',
  description   VARCHAR(255) NULL COMMENT '描述(如: 订单服务)',
  enabled       TINYINT(1)   NOT NULL DEFAULT 1 COMMENT '是否启用(1=启用, 0=禁用)',
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_service (service),
  UNIQUE KEY uk_api_token (api_token)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- ------------------------------------------------------------
-- 10. system_config : 系统动态配置（key-value）
-- ------------------------------------------------------------
CREATE TABLE IF NOT EXISTS system_config (
  config_key    VARCHAR(128) NOT NULL COMMENT '配置键(如 llm.model)',
  config_value  TEXT         NULL COMMENT '配置值',
  description   VARCHAR(255) NULL COMMENT '描述',
  updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (config_key)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```
