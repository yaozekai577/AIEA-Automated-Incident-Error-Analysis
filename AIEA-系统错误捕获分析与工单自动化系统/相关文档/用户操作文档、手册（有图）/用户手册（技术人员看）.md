## 1. 产品概述

### 1.1 AIEA 是什么

AIEA 是一款面向研发团队的 **AI 驱动的异常全生命周期管理平台**，将「异常捕获 → 智能去重 → AI 根因分析 → 群聊通知 → 工单闭环」全流程自动化，替代传统的人工翻日志—群里同步—手填工单的低效模式。

### 1.2 核心能力

| 能力 | 说明 |
|------|------|
| **错误捕获** | 通过轻量 SDK 或 Logback Appender 自动上报异常堆栈 |
| **智能去重** | 堆栈指纹归一化 + Redis 冷却窗口，同类错误不刷屏 |
| **AI 根因分析** | 调用大模型（OpenAI 兼容协议）生成结构化根因报告与修复建议 |
| **协作推送** | 自动推送飞书/钉钉群聊卡片消息，含摘要 + AI 分析 + 工单链接 |
| **工单闭环** | 自动创建内置工单（可选 Jira），支持认领、解决、关闭、重开全流程 |
| **管理控制台** | React Web UI，可视化管理服务注册、通知路由、LLM 配置、告警规则 |

### 1.3 系统架构

```
┌─────────────────┐   ┌──────────────────────┐
│ 业务 Java 服务   │   │ 本地服务 / 存量系统   │
│  + aiea-sdk     │   │  + Logback Appender  │
└────────┬────────┘   └──────────┬───────────┘
         │ HTTP 上报             │ HTTP 上报
         └───────────┬───────────┘
                     ▼
         ┌───────────────────────┐
         │     AIEA Server       │
         │  (Spring Boot 3.3)    │
         │                       │
         │  Ingest → Fingerprint │
         │  → Dedup → Pipeline   │
         │  → Analyze → Notify   │
         │  → Ticket             │
         └───────┬───────────────┘
                 │
     ┌───────────┼───────────┬────────────┐
     ▼           ▼           ▼            ▼
  MySQL 8    Redis 7    LLM API     飞书/钉钉
                        (OpenAI兼容)   Jira (可选)
```

### 1.4 用户角色

| 角色 | 职责 | 主要使用场景 |
|------|------|-------------|
| **研发工程师** | 业务系统接入 AIEA | 引入 SDK、初始化配置、上报异常 |
| **运维管理员** | 平台配置与运维 | 服务注册、通知路由、LLM 配置、告警策略 |
| **工单处理人** | 处理错误工单 | 认领工单、查看 AI 分析、推进解决 |
| **技术负责人** | 关注团队效率 | 查看仪表盘统计、错误趋势、工单分布 |

## 2. 快速入门

### 2.1 环境准备

| 依赖 | 最低版本 | 用途 |
|------|----------|------|
| JDK | 17 | AIEA Server 编译运行 |
| Maven | 3.8+ | 构建工具 |
| MySQL | 8.0 | 数据库 |
| Redis | 6.0+ | 缓存/去重/限流 |
| Node.js | 18+ | 前端开发（可选） |

### 2.2 五分钟体验流程

以下步骤将帮助您在 5 分钟内完成 AIEA 的部署和首次错误上报：

#### Step 1: 初始化数据库

```sql
-- 登录 MySQL 后执行
SOURCE d:/Java/ai开发比赛/AIEA/src/main/resources/db/init.sql;
```

#### Step 2: 构建并安装 SDK

```powershell
cd d:\Java\ai开发比赛\aiea-sdk
mvn clean install -DskipTests
```

#### Step 3: 配置并启动 AIEA Server

编辑 `src/main/resources/application.yaml`，确认数据库和 Redis 连接信息正确：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/aiea?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    username: root
    password: root
  data:
    redis:
      host: localhost
      port: 6379
```

启动服务：

```powershell
cd d:\Java\ai开发比赛\AIEA
mvn spring-boot:run
```

启动后验证：
- Swagger UI: http://localhost:8080/swagger-ui.html
- 健康检查: http://localhost:8080/actuator/health

#### Step 4: 注册服务获取 Token

```bash
curl -X POST http://localhost:8080/api/v1/service-registry \
  -H "Content-Type: application/json" \
  -d '{"service":"my-service","description":"我的服务"}'
```

记录返回的完整 `apiToken`（仅展示一次）。

#### Step 5: 上报第一个错误

```bash
curl -X POST http://localhost:8080/api/v1/errors \
  -H "Content-Type: application/json" \
  -H "X-AIEA-Token: tok_xxx" \
  -d '{
    "env": "local",
    "service": "my-service",
    "message": "NullPointerException: test error",
    "stack": "java.lang.NullPointerException\n\tat com.example.MyService.run(MyService.java:10)"
  }'
```

返回 `RECEIVED` 表示上报成功，系统将自动触发异步流水线进行 AI 分析和通知。

#### Step 6: 查看结果

访问 http://localhost:8080/api/v1/errors/1 查看错误详情，包括 AI 根因分析结果。

```
│                              ▼         │                        │
│  3. 配置 LLM (Base URL/Key/Model)     │                        │
│     配置飞书全局 Webhook               │                        │
│                                      │                        │
│  4. Token 交付给业务系统 ──────────────────────────────────►  │
│                                      │                        │
│                                      │  5. 引入 aiea-sdk      │
│                                      │     初始化 (Token+URL)  │

│                                      │     Aiea.capture(e)    │
│                                      │         │              │
│  7. AIEA 自动处理 ◄────────────────────────────┘              │
│     AI分析 → 群消息 → 工单                                     │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 方式一：SDK 对接（推荐）

适用于 Java 业务系统，支持手动捕获和全局异常处理器自动上报。

#### Step 1: 在 AIEA 控制台注册服务

在「服务注册」页面新增服务，系统自动生成专属 Token（仅展示一次，请妥善保存）。

或通过 API 注册：

```bash
curl -X POST http://localhost:8080/api/v1/service-registry \
  -H "Content-Type: application/json" \
  -d '{"service":"order-service","description":"订单服务"}'
```

#### Step 2: 引入 SDK 依赖

在业务系统的 `pom.xml` 中添加：

```xml
<dependency>
    <groupId>com.yzk</groupId>
    <artifactId>aiea-sdk</artifactId>
    <version>0.0.1-SNAPSHOT</version>
</dependency>
```

> **前提**：需先执行 `mvn install` 将 aiea-sdk 安装到本地 Maven 仓库。

#### Step 3: 初始化 SDK

在业务系统中创建配置类，应用启动时自动初始化：

```java
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Configuration;
import com.yzk.aiea.sdk.Aiea;
import com.yzk.aiea.sdk.AieaConfig;
import javax.annotation.PostConstruct;

@Configuration
public class AieaSdkConfig {

    @Value("${aiea.server-url:http://localhost:8080}")
    private String serverUrl;

    @Value("${aiea.api-token:}")
    private String apiToken;

    @Value("${aiea.service:my-service}")
    private String service;

    @Value("${aiea.env:dev}")
    private String env;

    @Value("${aiea.release-version:0.0.1}")
    private String releaseVersion;

    @PostConstruct
    public void initSdk() {
        Aiea.init(AieaConfig.builder()
                .serverUrl(serverUrl)
                .apiToken(apiToken)
                .service(service)
                .env(env)
                .releaseVersion(releaseVersion)
                .build());
    }
}
```

对应的 `application.yml` 配置：

```yaml
aiea:
  server-url: http://localhost:8080
  api-token: tok_xxx
  service: order-service
  env: dev
  release-version: 1.0.0
```

#### Step 4: 上报异常

**方式一：手动捕获上报**

```java
try {
    // 业务逻辑
} catch (Exception e) {
    Aiea.capture(e);  // 异步上报，不阻塞
    throw e;          // 按需重新抛出
}
```

携带额外上下文：

```java
Aiea.capture(exception, Map.of(
    "userId", currentUserId,
    "orderId", orderId,
    "traceId", MDC.get("traceId")
));
```

**方式二：全局异常处理器自动上报（推荐）**

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(Exception.class)
    public Map<String, Object> handleException(Exception e, HttpServletRequest request) {
        Map<String, Object> context = new HashMap<>();
        context.put("url", request.getRequestURL().toString());
        context.put("method", request.getMethod());
        context.put("remoteAddr", request.getRemoteAddr());

        Aiea.capture(e, context);

        log.error("全局异常捕获: {}", e.getMessage(), e);

        Map<String, Object> result = new HashMap<>();
        result.put("code", 500);
        result.put("message", e.getMessage());
        return result;
    }
}
```

> SDK 会自动采集 hostname、线程名、releaseVersion，并内置敏感信息脱敏。

### 4.3 方式二：Logback Appender 对接（零侵入）

适用于无法修改代码的存量系统，只需修改 `logback.xml` / `logback-spring.xml`。

#### Step 1: 注册服务获取 Token

同 4.2 Step 1。

#### Step 2: 引入依赖

```xml
<dependency>
    <groupId>com.yzk</groupId>
    <artifactId>AIEA</artifactId>
    <version>0.0.1-SNAPSHOT</version>
    <scope>provided</scope>
</dependency>
```

#### Step 3: 配置 Logback

在 `logback-spring.xml` 中添加 Appender：

```xml
<appender name="AIEA" class="com.yzk.aiea.logback.AieaLogbackAppender">
    <serverUrl>http://localhost:8080</serverUrl>
    <apiToken>tok_xxx</apiToken>
    <service>order-service</service>
    <env>prod</env>
</appender>

<logger name="com.yourcompany" level="ERROR" additivity="false">
    <appender-ref ref="AIEA"/>
    <appender-ref ref="CONSOLE"/>
</logger>
```

配置后，ERROR 级别日志会自动异步上报到 AIEA，无需改业务代码。

### 4.4 方式三：直接 HTTP 调用

适用于非 Java 环境（Python/Go/Node.js 等），直接调用 REST API：

```bash
curl -X POST http://localhost:8080/api/v1/errors \
  -H "Content-Type: application/json" \
  -H "X-AIEA-Token: tok_xxx" \
  -d '{
    "env": "prod",
    "service": "order-service",
    "message": "NullPointerException: Cannot invoke method on null object",
    "stack": "java.lang.NullPointerException\n\tat com.example.OrderService.process(OrderService.java:42)",
    "context": {
      "hostname": "prod-server-01",
      "traceId": "abc-123"
    }
  }'
```

**Python 示例**：

```python
import requests

response = requests.post("http://localhost:8080/api/v1/errors", 
    headers={
        "Content-Type": "application/json",
        "X-AIEA-Token": "tok_xxx"
    },
    json={
        "env": "prod",
        "service": "python-service",
        "message": "KeyError: 'user_id'",
        "stack": "Traceback (most recent call last):\n  File ...",
        "context": {
            "hostname": "python-server-01",
            "traceId": "trace-123"
        }
    }
)
print(response.json())
```

## 5. 管理控制台使用指南

前端管理控制台提供 8 个功能页面，覆盖全部管理操作。

### 5.1 仪表盘（Dashboard）

**路径**: `/dashboard`

**功能**: 全局统计概览，一页掌握系统运行状况。

**包含内容**:
- **核心指标卡片**: 事件总数、唯一指纹数、通知成功率、AI 分析数
- **AI 置信度分布**: 高（≥0.7）/ 中（0.4~0.7）/ 低（<0.4）占比
- **工单状态分布**: OPEN / IN_PROGRESS / RESOLVED / CLOSED 数量
- **环境分布**: local / dev / staging / prod 事件数
- **服务分布**: 各业务服务错误数排行
- **近 7 天错误趋势**: 折线图展示每日错误量
- **错误热力图**: 星期×小时的错误分布，帮助识别高频时段
- **智能洞察**: 系统自动分析异常趋势和需要关注的错误
- **系统健康度**: Redis/LLM/飞书 连通状态

### 5.2 错误事件列表（Error List）

**路径**: `/errors`

**功能**: 查看和管理所有错误事件。

**操作**:
- 按状态筛选（RECEIVED / ANALYZING / NOTIFIED / TICKETED / FAILED / SUPPRESSED）
- 按服务名筛选
- 关键词搜索（异常消息、服务名）
- 点击事件 ID 进入详情页
- 有工单关联的事件会显示工单标记

### 5.3 错误详情（Error Detail）

**路径**: `/errors/{id}`

**功能**: 查看单个错误事件的完整信息。

**包含内容**:
- **事件基本信息**: 指纹、环境、服务名、异常消息、状态
- **完整堆栈**: 代码堆栈详情
- **上下文**: 版本、hostname、线程名、traceId 等
- **AI 根因分析**: 根因描述、修复建议列表、置信度评分、使用的模型
- **通知记录**: 飞书/钉钉推送记录（渠道、HTTP 状态码、发送时间）
- **内置工单**: 关联的工单信息（含操作时间线）
- **Jira 工单**: 关联的 Jira Issue（如有）
- **操作按钮**: 重试流水线（对 FAILED 事件重新触发分析/通知/建单）

### 5.4 错误聚合（Error Groups）

**路径**: `/error-groups`

**功能**: 按指纹分组查看同类错误。

**包含内容**:
- 每个指纹的出现次数
- 首次出现时间 / 最近出现时间
- 状态分布
- 关联的服务名和异常消息

**使用场景**: 快速识别高频问题，了解哪些错误最频繁出现。

### 5.5 告警规则（Suppress Rules）

**路径**: `/suppress-rules`

**功能**: 管理告警抑制/冷却规则。

**包含内容**:
- 指纹、冷却窗口（秒）、命中次数、上次触发时间
- 实时冷却状态（每秒自动刷新，显示是否在冷却中及剩余时间）
- 关联服务、异常消息、环境、最新事件 ID
- 该指纹的事件总数

**操作**:
- 调整单个指纹的冷却窗口（1~86400 秒，即 1 秒到 24 小时）
- 冷却窗口越大，同类错误在越长时间内不会重复触发通知

### 5.6 服务注册（Service Registry）

**路径**: `/service-registry`

**功能**: 管理接入 AIEA 的业务服务。

**操作**:
- **注册新服务**: 填写服务名和描述，系统自动生成 Token（仅展示一次）
- **查看服务列表**: Token 脱敏展示（如 `tok_a****def`）
- **编辑服务**: 修改描述
- **启用/禁用服务**: 禁用后该服务上报将被拒绝（403）
- **重置 Token**: 生成新 Token，旧 Token 立即失效
- **删除服务**: 删除后该服务上报将被拒绝（401）

> **重要**: Token 仅在创建和重置时完整展示一次，请务必妥善保存。

### 5.7 通知路由（Notify Routing）

**路径**: `/notify-routing`

**功能**: 配置不同业务服务的通知推送路由。

**路由匹配逻辑**:
```
错误事件上报 → 查找 notify_routing 表
  │
  ├─ 匹配到 (service + channel) 且 enabled=true → 推送到该规则配置的专属 Webhook
  │
  └─ 未匹配或规则已禁用 → fallback 到全局 Webhook (application.yaml 中配置)
```

**操作**:
- 新建路由规则：选择服务名、渠道（飞书/钉钉）、填写 Webhook 地址
- 编辑/删除路由规则
- 启用/禁用路由规则
- **连通性测试**: 向指定路由的机器人发送测试消息，验证 Webhook 是否可达

**典型场景**:
```
order-service     + feishu    → 订单团队飞书群 Webhook A
payment-service   + feishu    → 支付团队飞书群 Webhook B
order-service     + dingtalk   → 订单团队钉钉群 Webhook C
其他未配置的服务               → 全局飞书 Webhook
```

### 5.8 工单管理（Tickets）

**路径**: `/tickets`

**功能**: 管理错误工单的完整生命周期。

#### 工单列表
- 按状态筛选（OPEN / IN_PROGRESS / RESOLVED / CLOSED / IGNORED）
- 按处理人筛选
- 关键词搜索
- 点击工单 ID 进入详情页

#### 工单详情
**包含内容**:
- 工单基本信息: 标题、状态、优先级、处理人
- 关联错误事件: 事件 ID、异常消息、指纹
- AI 根因分析: 根因描述、修复建议
- **修复提示词**: 一键复制功能，自动组装错误背景+代码位置+根因分析+修复建议为结构化 Prompt，可直接粘贴给 AI 编程助手辅助修复
- 操作时间线: CREATE / CLAIM / RESOLVE / CLOSE / IGNORE / REOPEN / PRIORITY / RECURRENCE 按时间排列

#### 工单操作
| 操作 | 说明 | 状态变化 |
|------|------|---------|
| 认领 | 指定处理人 | OPEN → IN_PROGRESS |
| 解决 | 填写解决方案 | → RESOLVED |
| 关闭 | 关闭已解决工单 | → CLOSED |
| 忽略 | 标记为忽略（填写原因） | → IGNORED |
| 重开 | 重新打开 | → IN_PROGRESS |
| 变更优先级 | 修改 P0/P1/P2/P3 | 不变 |

**工单状态机**:
```
OPEN → IN_PROGRESS → RESOLVED → CLOSED
                              ↘ IGNORED
RESOLVED/CLOSED/IGNORED → IN_PROGRESS (REOPEN)
```

**优先级说明**:
| 优先级 | 含义 | 判定规则 |
|--------|------|---------|
| P0 | 最高 | OOM、死锁 → 自动判定 |
| P1 | 高 | 空指针、SQL 异常 → 自动判定 |
| P2 | 中 | 默认优先级 |
| P3 | 低 | 手动设置 |

### 5.9 系统配置（Config）

**路径**: `/config`

**功能**: 查看和修改系统运行配置。

**包含内容**:
- **运行配置视图**: 只读展示当前生效的全部配置（密钥脱敏）
  - 接入配置: 已注册服务数、冷却时间、限流参数
  - LLM 配置: Base URL、模型名、API Key 是否已配置、缓存 TTL
  - 飞书配置: Webhook 是否已配置
  - Jira 配置: 是否启用、Base URL、项目 Key
  - 流水线配置: 是否启用、通知渠道、通知是否启用
  - 通知路由: 规则总数、已启用规则数
- **LLM 配置编辑**: 在线修改 Base URL / API Key / 模型 / 缓存 TTL，保存后立即生效
- **LLM 连通性测试**: 发送「你好」消息验证 API 可达性
- **飞书连通性测试**: 发送测试消息到飞书群

## 8. 常见问题与排障

### Q1: SDK 上报返回 401 Unauthorized

**原因**: Token 不匹配或服务未注册。

**解决**:
1. 在「服务注册」页面确认服务已注册且处于启用状态
2. 确认 SDK 配置的 `apiToken` 与注册时获取的 Token 一致
3. 如 Token 遗失，在服务注册页面点击「重置 Token」

### Q2: 同一错误反复推送群消息

**原因**: 冷却窗口设置过小或 Redis 连接异常。

**解决**:
1. 在「告警规则」页面查看该指纹的冷却时间，可在线调整（1~86400 秒）
2. 检查 Redis 连接是否正常（`/actuator/health`）
3. Redis 不可用时降级为放行（不抑制），但不影响主链路

### Q3: LLM 分析返回降级摘要

**原因**: LLM API 不可达、超时或返回格式异常。

**解决**:
1. 在「系统配置」页面点击「LLM 连通性测试」验证 API 可达性
2. 确认 `llm.base-url`、`llm.api-key`、`llm.model` 配置正确
3. 确认 LLM API 兼容 OpenAI `/chat/completions` 协议
4. 分析失败时会自动降级为规则摘要，不影响通知和建单流程

### Q4: Jira 工单创建失败

**原因**: Jira 未配置或权限不足。

**解决**:
1. 确认 `jira.base-url`、`jira.email`、`jira.api-token` 配置正确
2. 确认 API Token 有创建 Issue 权限
3. 可设置 `jira.mock-when-unconfigured: true` 在未配置时返回 Mock Key
4. local 环境默认不建 Jira（`jira.enable-for-local: false`）
5. **内置工单不依赖 Jira**，即使 Jira 未配置也能正常创建和管理工单

### Q5: local 环境上报后没有触发分析和通知

**检查**:
1. 确认事件状态不是 `SUPPRESSED`（冷却窗口内重复上报会被抑制）
2. 确认 `pipeline.enabled: true`
3. 确认 `pipeline.notify-enabled: true`
4. 查看服务端日志中 `aiea-pipeline-` 线程是否有异常

### Q6: 如何区分不同环境的错误

SDK 初始化时设置 `env` 字段（`local`/`dev`/`staging`/`prod`），不同环境可：
- 配置不同的通知路由（推送到不同群）
- local 环境默认不建 Jira 工单
- 仪表盘按环境维度统计分布

### Q7: Redis 不可用时系统还能工作吗

**可以**。Redis 不可用时，系统会自动降级：
- 去重/冷却：降级为放行（不抑制，同类错误会重复触发下游）
- 限流：降级为不限流
- LLM 缓存：降级为不缓存，每次都调用 LLM

主链路（错误接入 → AI 分析 → 通知 → 建单）不受影响。

### Q8: 工单的"修复提示词"是什么

工单详情页提供「修复提示词」一键复制功能，系统会自动从错误事件和 AI 分析结果中提取以下信息并组装为结构化 Prompt：
- 错误背景（服务名、环境、异常类型）
- 代码位置（从堆栈中提取）
- 根因分析（AI 生成的根因描述）
- 修复建议（AI 生成的建议列表）

复制后可直接粘贴给 AI 编程助手（如 Cursor、Copilot 等）辅助修复代码。

## 9. 最佳实践

### 9.1 环境隔离建议

| 环境 | 建议配置 |
|------|---------|
| `local` | 不建 Jira，推送到个人测试群或关闭通知 |
| `dev` | 推送到开发群，冷却窗口设为 300 秒 |
| `staging` | 推送到测试群，冷却窗口设为 600 秒 |
| `prod` | 推送到生产告警群，冷却窗口设为 1800 秒，启用 Jira |

### 9.2 冷却窗口调优

| 场景 | 建议冷却时间 | 说明 |
|------|-------------|------|
| 开发环境 | 120~300 秒 | 快速反馈，不过度抑制 |
| 生产环境 | 600~1800 秒 | 避免告警风暴 |
| 高频已知问题 | 3600~86400 秒 | 已知问题临时调大冷却 |

### 9.3 通知路由规划

建议为每个团队/服务配置专属通知路由，而非全部使用全局 Webhook：
- 订单服务错误 → 订单团队群
- 支付服务错误 → 支付团队群
- 基础设施错误 → 运维群

### 9.4 SDK 使用建议

- **推荐使用全局异常处理器**：一次配置，全局生效，无需在每个 try-catch 中手动调用
- **携带有价值的上下文**：在 `capture()` 时附带 userId、orderId、traceId 等业务信息，帮助 AI 更准确分析
- **生产环境设置 releaseVersion**：版本号能帮助快速定位引入问题的版本

### 9.5 安全建议

- Token 妥善保存，不要提交到代码仓库
- 生产环境通过环境变量或配置中心注入 Token 和 API Key
- 定期检查「服务注册」页面，清理不再使用的服务
- 定期检查「告警规则」页面，关注高频错误的冷却命中情况
